#### Brainstorming

**M : Must have (doit avoir)**  
Le strict minimum vital. Sans ça, le produit est inutilisable, illégal, dangereux ou la livraison est considérée comme un échec. Test : _"si on ne livre pas ça, est-ce que ça sert encore à quelque chose ?"_ Si la réponse est non, c'est un Must. Exemple : sur un site e-commerce, pouvoir payer une commande.

**S : Should have (devrait avoir)**  
Important, à forte valeur, mais pas bloquant. Le produit fonctionne sans, avec un contournement possible (même pénible). On les inclut si possible dans la livraison. Exemple : recevoir un mail de confirmation de commande.

**C : Could have (pourrait avoir)**  
Le "nice to have". Petit confort, faible impact s'il manque. Ce sont les premiers éléments sacrifiés en cas de retard. Exemple : suggestions de produits similaires.

**W : Won't have (n'aura pas, _cette fois_)**  
Ce qu'on décide explicitement de **ne pas faire dans cette itération/release**. Attention : ça ne veut pas dire "jamais", mais "pas maintenant". L'intérêt est de cadrer le périmètre et d'éviter le scope creep. Exemple : application mobile native, reportée à une version ultérieure.
